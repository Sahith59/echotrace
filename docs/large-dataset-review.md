# Large public datasets for HEARSAY audio detection

Checked 2026-09-25 against dataset creators' pages, author-hosted repositories, and the ASVspoof organizers' release. This review concerns **public-corpus development and evaluation**, not the unreleased sponsor data. No large audio corpus was downloaded for this review.

## Recommendation

Use **ASVspoof 5 Track 1** as the main substantial, reproducible English training/development corpus if the project has enough storage and compute. Its official training and development protocols are labeled and usable for binary detection, with different speakers and attack algorithms across those partitions. Train or adapt only on its training partition; select checkpoints and any threshold on its development Track 1 partition. Freeze the model before evaluating the official evaluation Track 1 partition. The [organizers' Zenodo release](https://zenodo.org/records/14498691) is 142.3 GB including all audio, but the train and development archives alone are about **57.5 GB** (37.5 + 20.0 GB, from rounded archive sizes), and the protocol archive is only 20.7 MB. The archives are already divided by T, D, and E, so the evaluation audio does not have to be downloaded for initial training.

For multilingual coverage, add **MLAAD v8** as a separate synthetic training resource only after obtaining matching genuine M-AILABS audio and building source-aware splits. Do not treat its synthetic-only collection as a ready binary benchmark. Use **In-the-Wild** as a locked, real-world English external test and **Deepfake-Eval-2024 audio** as a later locked contemporary external test, subject to its gated access and evaluation-only terms. These tests measure public-domain generalization; neither predicts the HEARSAY score or substitutes for the sponsor's held-out set.

### ASVspoof 5 protocol usability

The [official README](https://zenodo.org/records/14498691/files/README.txt?download=1) maps `flac_T_*.tar` to training, `flac_D_*.tar` to development, and `flac_E_*.tar` to evaluation. `ASVspoof5.train.tsv`, `ASVspoof5.dev.track_1.tsv`, and `ASVspoof5.eval.track_1.tsv` are the relevant binary detection lists. Each row contains ten space-separated fields (the README mistakenly calls them “FIVE columns”): `SPEAKER_ID FLAC_FILE_NAME SPEAKER_GENDER CODEC CODEC_Q CODEC_SEED ATTACK_TAG ATTACK_LABEL KEY TMP`. The `KEY` is `bonafide` or `spoof`. Resolve `FLAC_FILE_NAME` inside its corresponding T/D/E extracted directory and verify every protocol ID maps to a file. Use speaker, codec source, and attack metadata for audits and stratified reporting; **do not feed metadata, file names, or split IDs into the classifier**.

The development archive has 142,134 audio files, but **1,184 are Track 2 enrollment clips**, so the Track 1 development protocol covers 140,950. Likewise, the evaluation archive has 681,872 files, but the Track 1 protocol covers 680,774. Counting archive files as classification trials would inflate the denominators. The [database paper](https://doi.org/10.1016/j.csl.2025.101825) describes 400 training speakers and separate development speakers, with eight TTS/VC algorithms in training and different algorithms in development. Its approximate class counts are 19k genuine / 164k spoof for training and, for Track 1 development, roughly 31k genuine / 110k spoof. Use protocol rows for exact counts. The official [Phase 2 evaluation plan](https://www.asvspoof.org/) should govern comparisons with published challenge scores.

### Reproducible evaluation design

1. Pin dataset version/revision, archive checksums, protocol checksums, license files, and a manifest of selected IDs. MLAAD's live [project page](https://deepfake-total.com/mlaad) now describes **version 9** (>1,000 hours, >50 languages, >175 models), so its current `main` is **not an immutable v8 reference**. Locate and pin an actual v8 repository commit or archived release before quoting v8 experiments. The HF card's language tags currently list only eight languages and are not a reliable count for the full release.
2. For ASVspoof 5, train on T, develop on D Track 1, and evaluate once on E Track 1. Keep original utterance units for headline metrics. Audit source-linked codec variants (`CODEC_SEED`) and speakers; report AUROC, EER, false-positive/false-negative rates at a development-chosen threshold, and slices by attack, codec, and genuine recording condition. Do not tune on E. Account for the strong class imbalance with both class-sensitive and threshold-free measures.
3. If adding MLAAD, combine its generated clips with permitted M-AILABS originals, then group by original recording/reference speaker and hold out TTS systems or architectures for a meaningful external test. Balance genuine and spoof examples **within each source/language condition** to avoid learning corpus provenance instead of synthesis artifacts. Record all source licenses and clip relationships.
4. Score the untouched model on In-the-Wild and, after access, Deepfake-Eval-2024 audio. Keep each as a separate dataset result; do not pool with ASVspoof E or fit a threshold on these external tests. Inspect errors by language, compression, recording condition and speaker where metadata permits. If an ASVspoof or MLAAD pretrained checkpoint already saw a test corpus, label that result contaminated or omit it as an independent test.
5. When sponsor data becomes available, independently audit its distribution, labels, metric, legal terms and CSV format. Run the frozen public baseline first, then any sponsor-authorized adaptation with sponsor-provided partitions. Report sponsor metrics separately; public access never implies sponsor authorization or sponsor-distribution validity.

## Practical constraint

The best *large ready-to-train* choice here is ASVspoof 5, because it has official labeled T/D protocols and directly downloadable split archives. MLAAD v8 is larger and multilingual but synthetic-only and noncommercial; its value depends on genuine-source acquisition and careful version/split construction. Deepfake-Eval-2024's evaluation-only rule rules it out for training. In-the-Wild is deliberately small enough to serve as a realistic external check rather than the core training set.
