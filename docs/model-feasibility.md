## Exact upstream behavior to preserve or adapt consciously

- The model's SincConv defaults to **16,000 Hz** and one channel ([source](https://github.com/clovaai/aasist/blob/main/models/AASIST.py)). Decode WAV/MP3/M4A through FFmpeg to mono float PCM at 16 kHz. Record original metadata and the resampling/downmix policy; do not peak-normalize or remove silence by default. This adapts the source code's FLAC reading to arbitrary containers and therefore needs fixture checks.
- The [evaluation dataset](https://github.com/clovaai/aasist/blob/main/data_utils.py) takes the **first 64,600 samples** (4.0375 seconds at 16 kHz) and repeats short waveforms to that length. It does not apply sample-level normalization. Empty waveforms need explicit rejection because repeat padding divides by their length. Preserve float waveform scale expected by `soundfile.read`/FFmpeg float PCM.
- The [configuration](https://github.com/clovaai/aasist/blob/main/config/AASIST-L.conf) sets `nb_samp=64600` and the AASIST-L layer sizes. Construct `Model(config["model_config"])`, load the matching state dict, call `.eval()` and run with `torch.inference_mode()`. The forward call returns `(embedding, logits)`; keep both class logits in the internal result. Loading a `.pth` state dict should use a trusted pinned source, `map_location`, and `weights_only=True` where compatible with the checkpoint.
- Label polarity is explicit in [data_utils.py](https://github.com/clovaai/aasist/blob/main/data_utils.py): **1 = bonafide; 0 = spoof**. The [official evaluation code](https://github.com/clovaai/aasist/blob/main/main.py) outputs `logits[:,1]` as a *bonafide* score. The internal synthesis direction must be the opposite: use `logits[:,0] - logits[:,1]` as a spoof margin, or `softmax(logits, dim=-1)[:,0]` as a bounded **uncalibrated model score**. Neither is a calibrated probability. Verify polarity on known-label audio before any UI or CSV mapping.
- The [upstream `main.py`](https://github.com/clovaai/aasist/blob/main/main.py) deliberately raises `ValueError("GPU not detected!")` on CPU and assumes the ASVspoof directory/protocol files. A standalone inference adapter can use the model directly on CPU/MPS; upstream training/evaluation CLI is unsuitable for this Mac and for arbitrary uploads.

For recordings longer than 4.0375 seconds, upstream evaluation truncates to the start. That would miss later edits. For this product, use deterministic overlapping 64,600-sample windows over the whole file, include a final window anchored to the end, and record each interval in original time coordinates. Repeat-pad only genuinely short inputs. Start with a documented file-level aggregation such as maximum spoof score, but **select the aggregation using sponsor validation data**; a maximum can inflate scores on long clips. The official single-crop result is useful as a parity reference only. Do not describe window scores as precise splice boundaries.

## Immediate feasibility gate

1. Create Python 3.12 environment and install PyTorch, NumPy, `soundfile` if needed for parity checks, and the chosen decoder path. Upstream `requirements.txt` includes `torchcontrib` for training/SWA; a pure inference adapter does not need it. Pin versions after resolving compatibility.
2. Download source/config/checkpoint from one upstream commit, verify file hashes, instantiate AASIST-L, load state dict strictly, and run one deterministic 64,600-sample tensor on CPU. If MPS is tested, compare logits against CPU within a declared tolerance and measure latency; CPU remains usable regardless.
3. Decode real WAV/MP3/M4A fixtures with FFmpeg and check 16 kHz mono output, amplitude range, duration, empty/silent behavior, and 64,600-sample shape. Compare adapter logits with the official evaluation preprocessing on the same FLAC fixture when available.
4. Run known bonafide and spoof clips, check class direction, inspect failures, then evaluate on grouped sponsor validation data once supplied. Log cold/warm runtime, per-window cost, file lengths, score distributions, and observed metrics. Only then choose scoring/aggregation/calibration.

The sponsor dataset, official CSV schema, metric, and event rules are not present in this workspace. Therefore no HEARSAY performance, calibrated percentage, threshold, or final export can yet be asserted.

## Alternative assessed

The [Sara1708 wav2vec2 anti-spoof checkpoint](https://huggingface.co/Sara1708/deepfake-audio-wav2vec2) is Apache-2.0 and documents 16 kHz, 4-second windows. Its card requires a [custom repository inference wrapper](https://github.com/Saracasm/deepfake-audio-detection) rather than direct `AutoModelForAudioClassification` loading; its roughly 95M-parameter backbone is materially heavier than AASIST-L. The card explicitly reports poor cross-dataset results on WaveFake and codec sensitivity. Its published EER values are source-reported benchmark results, **not** forecasts for HEARSAY. Keep it as a second-model experiment only if AASIST-L loads and sponsor validation indicates value. A generic wav2vec speech encoder alone is not an anti-spoof detector.

If official AASIST-L cannot pass the checkpoint/known-label smoke test within a bounded attempt, try the [full official AASIST checkpoint](https://github.com/clovaai/aasist/blob/main/models/weights/AASIST.pth) with its own config (1,281,532 bytes), then the documented wav2vec2 candidate. Do not silently substitute DSP heuristics or fabricate scores.

## Local synthetic-speech wiring check

On 2026-09-25, `/usr/bin/say` generated an AI speech fixture from: “This recording is a synthetic speech demonstration for audio analysis. Please verify important messages through a trusted channel.” FFmpeg encoded the resulting AIFF to WAV (16 kHz mono PCM), MP3 (128 kb/s), and M4A (AAC 128 kb/s). The samples and output JSON remain under ignored `backend/artifacts/`; the WAV SHA-256 is `76ae4c4538ef036007820cf9660de944a578865db1f191c67453f5f62941b188`. Each file covered about 8 seconds in two model windows. On this machine the CLI returned uncalibrated spoof scores of **0.0299 WAV, 0.0292 MP3, and 0.0355 M4A**. Cold command wall time was roughly 1.6 seconds per file; reported analysis runtime was roughly 0.9 seconds per file. These are observations for one known-synthetic local fixture, not validation metrics. The low scores show that this checkpoint can miss at least this synthetic voice; validation on sponsor data is essential before using a score as a likelihood estimate.

`tests/test_real_integration.py` regenerates local macOS TTS in a temporary directory and checks that API and CLI return the same source hash, model/config provenance, window logits, and score. The focused suite (`test_pipeline.py` plus this integration test) passed 8/8. The pipeline repeats short inputs to 64,600 samples; longer files use nonoverlapping windows plus an end-anchored final window, so the last window may overlap the previous one. It currently takes the unweighted mean of uncalibrated spoof softmax values. This policy is recorded in each result and remains unvalidated. Non-speech detection is not implemented; every scored result carries a speech-presence limitation, and very quiet audio returns a null score.
